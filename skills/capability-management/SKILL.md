# 能力管理

Xiaoman 面向用户只提供两类可扩展能力：

- **Skill**：`SKILL.md` 形式的知识与工作流程，告诉模型应该怎样完成一类任务。
- **MCP 工具**：本地或远程 MCP server 提供的可执行工具，让模型读取外部数据或执行操作。

QQ、微信、企业微信、记忆引擎和调度器属于系统组件，不是用户安装的第三类扩展。仓库内部仍可使用扩展模块装配这些组件，但不得把内部实现暴露成“插件市场”。

## 先判断来源类型

用户说“安装插件”时，不要直接假设包类型。先检查项目：

1. 含 `SKILL.md`，且主体是说明、规则或工作流：按 Skill 安装。
2. 声明 MCP server、MCP transport，或可通过 stdio / Streamable HTTP 提供 tools：按 MCP 接入。
3. 同时提供 Skill 与 MCP：分别安装，Skill 负责使用方法，MCP 负责执行能力。
4. 普通 Python/Node 库既不是 Skill 也不是 MCP；只有系统开发任务才考虑把它接入内部组件层。

不要为了兼容某个仓库重新发明 Xiaoman 私有的包格式。优先使用项目原生的标准入口。

## 安装 Skill

在“技能”页面填写 Git 仓库地址；如果 Skill 位于仓库子目录，同时填写子目录和可选版本。安装器会把它放入独立的用户 Skill 目录，保留来源与版本信息，并支持单独卸载。

安装完成后立即重新读取技能目录，不要求重启 Gateway。不得覆盖不受安装器管理的同名本地 Skill。

## 安装 MCP

优先使用“MCP 工具”页面的推荐目录。目录没有的项目，按官方说明收集：

- 本地 MCP：启动命令、参数、工作目录和必要环境变量。
- 远程 MCP：HTTPS 地址、transport、认证方式。

远程服务优先使用 Streamable HTTP；需要用户账户授权时使用 OAuth PKCE，不索要或回显明文令牌。密钥应进入安全凭据存储，而不是普通配置文件。

安装后确认连接状态和实际工具列表。连接失败时报告真实错误，不把“配置已保存”当成“已经可用”。

## 卸载与边界

- 卸载 Skill 只移除该 Skill 的受管目录。
- 卸载 MCP 时断开连接、移除配置与凭据；若有 Xiaoman 单独创建的隔离运行环境，再一并移除。
- 不删除用户项目数据，不删除第三方应用账户中的内容。
- 对外发消息、写入云服务、删改文件等仍由统一权限系统审批；能力来源不会绕过权限。

## 回答方式

向用户说明最终安装成了 Skill 还是 MCP、来源是什么、当前是否真正连接、如何卸载。避免继续使用含糊的“插件”称呼。
