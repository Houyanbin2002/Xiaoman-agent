# 小满长期记忆系统

小满的记忆不是一个无限增长的上下文文件，也不是三套相互复制的数据库。运行时由
`core.memory.coordinator.CompositeMemoryEngine` 统一协调三个边界清楚的记忆域：

| 记忆域 | 保存什么 | 唯一真相源 | 主要用途 |
|---|---|---|---|
| 关于我 | 稳定事实、偏好、关系、明确要求、少量重要经历 | `personal.db` | 聊天、我的一天、主动协助 |
| Agent 执行经验 | 工具经验、项目约定、环境信息、可复用流程与决策 | `memory2.db` 的执行经验表 | 执行任务前避坑、复用成功做法 |
| 过往回忆 | 原始对话形成的关键词、向量和联想图索引 | `sessions.db/messages` | 找回完整经历并回源原文 |

`akasha.db` 只是 `sessions.db` 的可重建索引，不是另一份聊天记录；删除索引不会删除原始对话。

## 一轮对话怎样使用记忆

```text
当前消息
  ├─ 小型核心记忆（关于我，固定字符预算）
  ├─ 与当前问题相关的个人记忆
  ├─ 作用域匹配且仍可靠的 Agent 执行经验
  └─ Akasha 找到的过往对话片段（带 source_ref）
        ↓
      模型回答或调用工具
        ↓
  ├─ 原始消息提交到 sessions.db，Akasha 更新派生索引
  ├─ 实际工具结果更新所用执行经验的成功/失败证据
  └─ 持久化语义批次一次提取近期活动、个人候选、任务事件、主动规则和执行经验
```

个人核心记忆和按问题检索的个人记忆会去重。Agent 执行经验不会进入“关于我”，过往对话也不会
因为被检索过就自动升级成用户事实。

## 统一后台语义批次

语义提取不是每轮都调用模型。普通对话在空闲、切换会话、关闭程序或累计到批次阈值时处理；用户
明确纠正/规定、提醒或免打扰规则，以及高价值工具失败 Episode 会提前触发。一次模型调用接收两种
彼此分离的证据视图：

- 对话证据：用户消息和必要的相邻 Agent 上下文，用于近期活动、个人记忆、任务事件和主动规则；
- 执行证据：经过脱敏、截断和价值预筛的工具 Episode，用于执行经验。

普通单次工具成功不会进入模型。失败后换方法成功、连续失败、权限/版本/平台/必填参数限制，以及
可验证的非显然多步骤流程才构成长期执行经验候选。语义模型只给出候选、来源、置信度和证据引用；
`user_locked`、生命周期、冲突淘汰以及成功/失败计数由各领域治理器确定。

批次先以 `prepared` 状态写入 `sessions.db`，再按消费者分别投递并记录回执。程序中断时，启动过程
会从会话游标重建尚未分析的批次，或只重试尚未成功的消费者，不会让已成功领域重复写入。

## 关于我：统一治理的个人记忆

个人记忆存储在 `personal.db`，自动发现和“记住这个”使用同一套治理：

- 来源与置信度；
- 读取、写入权限和敏感级别；
- 用户锁定与可选到期时间；
- 冲突进入待确认，不静默覆盖；
- 新版本替代旧版本，保留修订历史；
- 临时状态和历史事件只在排序时衰减，稳定事实与偏好不因时间自动失真。

每轮始终可见的核心记忆有硬字符预算，只选择高价值的稳定事实、偏好、关系和明确要求。其余记录
保留在数据库中，只有与当前问题相关时才召回。个人数据量通常很小，因此向量旁路直接保存在
`personal.db/personal_memory_embeddings` 并做精确余弦扫描，再与关键词、类型、置信度、上下文和
时间语义共同排序；嵌入服务不可用时会自动降级到确定性的关键词排序。

## Agent 执行经验：按结果而不是按曝光强化

执行经验有独立的领域模型和仓储。每条经验至少包含：

- 类型：环境、项目约定、工具经验、流程、决策或能力边界；
- 作用域：全局、工作区、项目、工具或插件；
- 平台、环境指纹和可选版本约束；
- 候选、已验证、可能过时、已停用或已替代状态；
- 成功次数、失败次数、最后验证时间和证据引用。

召回前先做作用域硬过滤，再结合语义相关度、作用域具体度和可靠性排序。仅仅“被模型看到”不会
增加可靠性；Agent 必须在内部明确标记实际采用，而且相关工具真实执行成功或失败，才会更新证据。
连续失败会把学习到的经验标成过时或停用；用户明确规定的规则不会被自动停用。重复验证成功的
流程可以进入技能晋升候选，但不会自动生成技能。

## 过往回忆：Akasha 派生索引

Akasha 对 `sessions.db/messages` 建立：

- 关键词检索；
- 向量语义检索；
- 对话节点之间的联想边和激活状态。

召回结果携带消息 `source_ref`。模型若要依据具体原文作答，应继续使用
`fetch_messages(source_ref)` 读取真相源。`akasha.db` 可以从 `sessions.db` 重建，详细重建命令见
`plugins/akasha/REBUILD.md`。

## Markdown 文件现在负责什么

`memory/` 下的文件不再共同组成长期记忆数据库：

| 文件 | 当前职责 |
|---|---|
| `SELF.md` | 小满的自我说明，不存用户事实 |
| `RECENT_CONTEXT.md` | 从近期活动生成的有界、去重、跨会话摘要，帮助助手了解最近在忙什么 |
| `HISTORY.md` / `journal/` | 近期活动的追加式人类可读时间线，不作为长期偏好或规则的权威来源 |

新候选由 `sessions.db` 中的持久化语义批次直接进入个人记忆治理，不再经过 Markdown
缓冲文件。

## 场景接入

- 普通聊天：自动注入核心个人记忆、相关个人记忆、执行经验和相关过往回忆。
- 我的早晚流程：先用 `personal_context` 读取计划、承诺与健康状态，再用 `recall_memory` 核对相关
  个人记忆或原始对话。
- 主动协助：系统提示中包含受预算约束的核心个人记忆；评估内容兴趣时可调用统一
  `recall_memory`，不会读取无关敏感记录。
- Agent 工具任务：只召回与当前工作区、项目、工具和版本匹配的执行经验，并根据本轮真实结果更新
  可靠性。

## 主要代码边界

| 位置 | 职责 |
|---|---|
| `core/memory/coordinator.py` | 三个记忆域的查询、写入和工具路由 |
| `core/memory/governed.py` | 个人记忆治理、核心快照和个人检索入口 |
| `core/memory/personal_core.py` | 小型核心记忆预算与选择 |
| `core/memory/personal_retrieval.py` | 个人记忆权限过滤、类型化排序和时间语义 |
| `core/memory/personal_semantic.py` | 个人记忆向量同步、混合召回与降级 |
| `core/memory/execution.py` | Agent 执行经验领域模型、作用域和可靠性 |
| `core/conversation_semantics/evidence.py` | 对话证据、工具 Episode 预筛、预算和脱敏 |
| `core/conversation_semantics/` | v3 统一分析协议、持久批次、恢复和分消费者回执 |
| `memory2/execution_store.py` | 执行经验持久化和旧 procedure 迁移 |
| `memory2/execution_retriever.py` | 执行经验混合召回与独立提示词块 |
| `infra/persistence/personal_memory_vector_store.py` | `personal.db` 内的小规模精确向量旁路 |
| `plugins/akasha/` | 可回源、可重建的完整经历索引 |

Dashboard 的记忆管理对应四个产品视图：关于我、Agent 经验、过往回忆、待确认。这里的分类与后端
所有权一致，不再用一个“长期记忆”列表混放用户事实、流程和聊天索引。
