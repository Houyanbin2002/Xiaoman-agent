# 小满功能清单

这是一个可改造成个人 AI 助手的 Agent 项目。它不只是一个聊天机器人，而是一套带长期记忆、工具调用、Skill/MCP 扩展、主动推送和后台自主任务能力的个人智能体框架。

## 项目定位

Xiaoman Agent 的核心目标是让 AI 从“被动回答问题”升级为“能长期陪伴、主动观察、适时提醒、自动处理后台任务”的个人助手。

它适合用来构建：

- 个人 AI 助手
- Telegram / QQ / 飞书机器人
- 带长期记忆的聊天伙伴
- 主动推送信息的订阅助手
- 可扩展工具型 Agent
- 可扩展的个人自动化系统

## 核心功能

### 1. 多模型 LLM 接入

项目通过 OpenAI-compatible Chat Completions 接口接入大模型，支持配置主模型、轻量模型、视觉模型和 Agent 专用模型。

主要能力包括：

- 主模型用于复杂对话、推理和工具调用
- 轻量模型用于记忆判断、查询改写、快速分类等低延迟任务
- 视觉模型可作为图片理解能力补充
- 支持自定义 `base_url`，方便接入 DashScope、DeepSeek、OpenAI 兼容服务等
- 支持 reasoning / thinking 类参数的配置和适配

### 2. 被动对话 Agent Loop

用户发消息后，系统会进入完整的 Agent 回合流程：

```text
用户消息 -> 记忆检索 -> Prompt 渲染 -> LLM 推理 -> 工具调用 -> 回复生成 -> 对话归档
```

亮点：

- 支持多轮工具调用
- 支持流式回复
- 支持工具调用失败后的恢复和重试
- 支持上下文窗口控制
- 支持工具搜索，避免一次性暴露过多工具
- 支持统一任务中心，把独立步骤交给隔离的 Subagent 执行并持续跟踪

### 3. 统一持久化任务中心

项目内置统一 Task Runtime，用来处理不能在一次对话内可靠完成的后台或复杂任务。Workflow 是内部状态机，Subagent 是其中一种步骤执行器，不再作为另一套任务系统暴露。

支持：

- 按依赖关系执行多个 Agent 步骤
- 独立调研、分析和脚本步骤可交给隔离的 Subagent，并把结果写回任务步骤
- `wait_user`：暂停并等待用户补充信息
- `approval`：在外部写操作前等待用户审批
- 自动重试和失败阻塞
- 进程重启后恢复被中断的步骤
- SQLite Task Ledger、版本号和完整事件记录
- 完成、等待和失败时主动通知原会话

Agent 通过 `task_create` 创建任务，通过 `task_manage` 查询、继续、审批、重试或取消。短任务仍由当前回合直接完成。状态继续保存在工作区的 `workflows.db`，兼容已有数据。

### 4. 长期记忆系统

项目内置面向个人助手的长期记忆机制，不只保存聊天记录，还会自动提取结构化事实。

长期记忆以数据库为准：

- `personal.db`：受治理的个人事实、偏好、关系与临时状态
- `sessions.db`：待分析语义批次及其投递状态
- `memory2.db`：经过实际执行结果验证的 Agent 经验

Markdown 支持文件包括：

- `HISTORY.md`：时间线事件
- `RECENT_CONTEXT.md`：近期上下文摘要
- `SELF.md`：助手自我设定

系统通过持久化语义批次统一分析对话证据和高价值工具 Episode，一次产生近期活动、个人候选、任务事件、主动规则与执行经验；普通单次工具成功不会沉淀。为了减少模型调用和 prompt cache 波动，普通对话按空闲/会话切换/批次阈值处理，明确纠正、提醒、免打扰和关键失败信号才提前触发。

可选的语义记忆引擎还支持向量检索，让助手能按语义召回历史偏好、经历和事实。

面向个人助手的结构化记忆还增加了一层记忆治理：

- 区分事实、偏好、临时状态和历史事件
- 记录来源、写入时间、可信度、敏感类别和访问策略
- 支持修改、锁定、有效期、软遗忘和连历史一起彻底删除
- 新内容与现有事实冲突时进入待确认队列，不自动覆盖
- 健康、情感、账号、关系、位置和财务信息使用分级权限
- 可完整导出记录、修订历史和冲突处理记录

Memory v2 负责语义召回，`personal.db` 中的治理层负责结构化事实和授权，两者不会互相冒充事实源。

### 5. 主动推送 Proactive

这是项目最有特色的能力之一。Agent 可以在没有用户提问时，根据订阅源、上下文和重要程度主动联系用户。

主动推送流程：

```text
定时轮询 -> 收集 alert/content/context -> LLM 判断价值 -> 去重 -> 推送或跳过
```

支持的数据类型：

- `alert`：高优先级告警，适合直接推送
- `content`：内容流，由 LLM 逐条判断是否值得说
- `context`：背景上下文，低概率注入用于辅助判断

系统还有电量模型和冷却机制，避免过度打扰用户。

在通用 Proactive 之上，小满还会直接理解结构化个人事件。目前内置规则包括：

- 会议临近但材料未准备
- 截止日期临近或已逾期且进度不足
- 连续睡眠不足却安排高强度训练
- 待办持续延期
- 超过设定周期没有联系重要的人
- 情绪签到连续下降
- 网页、RSS、邮件或项目等监控来源的内容指纹真正变化

主动消息会明确写出“为什么现在提醒”，并带有已处理、稍后提醒、忽略和关闭同类提醒入口。规则、阈值摘要、冷却时间、洞察状态和底层投递日志可在 Dashboard 的“主动协助”页面管理。外部数据通过标准 MCP 接入。

### 6. Drift 空闲任务

当没有值得推送的内容时，Agent 可以进入 Drift 模式，执行预先定义的后台任务。

Drift 任务通常写成 `SKILL.md`，适合做：

- 自我诊断
- 长期记忆审计
- 用户画像补全
- 信息整理
- 定期检查某些资料
- 后台调研和总结

这让助手不只是“等你问”，还可以在空闲时主动维护自己的知识和状态。

### 7. Skill 与系统组件

Skill 通过标准 `SKILL.md` 独立安装，为模型提供任务方法和操作流程。记忆后端、消息渠道和生命周期模块属于内部系统组件，由启动装配层管理，不进入面向用户的扩展市场。

### 8. MCP 与外部工具集成

项目支持通过 MCP 扩展外部能力，把不同工具服务器挂载进 Agent。

适合接入：

- RSS / 信息源
- 搜索服务
- 本地工具
- 第三方平台 API
- 文件、数据库、知识库
- 自定义自动化能力

Agent 可以根据任务动态发现和调用工具，也可以在 Drift 中挂载 MCP server 完成后台任务。

### 9. 多频道接入

项目支持多个通信入口，适合把同一个个人助手接到不同平台。

当前配置中可见的频道包括：

- CLI / TUI
- Telegram
- QQ
- 官方 QQBot
- 飞书

频道层和 Agent 核心解耦，后续可以继续扩展到更多 IM、Webhook 或内部系统。

### 10. 任务调度与提醒

内置 SchedulerService 和 schedule 工具，可让 Agent 创建、查看、取消定时任务。

可用于：

- 定时提醒
- 周期性检查
- 后台任务恢复
- 主动推送节流
- 自动化计划执行

调度数据保存在工作区中，服务重启后可以恢复任务。

### 11. Web Dashboard

项目内置 Dashboard 服务，默认端口为 `2236`。

Dashboard 可用于：

- 查看运行状态
- 管理记忆相关能力
- 查看 proactive 状态
- 管理 Skill 与 MCP 工具
- 为个人助手提供可视化管理入口
- 通过“我的一天”管理承诺、计划、健康观测、签到和提醒策略
- 启动晨间简报、晚间回顾和承诺捕获任务
- 在“记忆治理”中处理冲突、授权、锁定、有效期、导出和彻底删除
- 在“主动协助”中查看提醒理由、稍后处理、关闭同类规则和调整冷却时间

### 11.1 统一个人数据与生命周期

工作区中的 `personal.db` 是结构化个人数据的事实源，统一保存：

- 个人资料与偏好边界
- 承诺和待办
- 日程与每日计划
- 健康观测与主观签到
- 通知策略
- 带治理信息的长期事实

每条记录都有来源、可信度、敏感等级、有效期、用户锁定、自动更新策略、版本号和生命周期状态。系统支持确认、过期、替代和遗忘；遗忘时会清空内容并脱敏历史快照。

同一个数据库还提供可靠事件收件箱、去重键、租约重试、死信状态、幂等操作、审批和审计记录。当前单用户本地部署不需要 Redis 或独立消息队列。

Memory v2 与 `sqlite-vec` 继续负责语义检索和对话记忆，`personal.db` 负责结构化个人事实，两者职责不同。

### 11.2 个人节奏与机会决策

“个人节奏”不是为每个生活场景单独启动一条流程。系统会把当前时间、可用时长、场景、专注状态、精力、截止风险和长期事项合成同一份上下文，再决定推荐、延后提醒或保持安静。

当前支持：

- “我现在有 15/30/60/90 分钟”的动态任务推荐
- 日常、出门、回家、睡前和旅行场景
- 25/50/90 分钟专注与统一免打扰策略
- 关系联络周期和重要日期
- 订阅、账单与续费
- 旅行时间、准备清单与快捷勾选
- 目标进度、周报、月报和时间进度偏差
- AI 沉淀的周期、指定时间、长期无进展或条件触发关注
- 根据接受、忽略和暂缓反馈调整实际冷却时间与表达方式

推荐来源、报告贡献者和主动评估器都是注册式扩展点。后续 Notion、健身、日历等 MCP 接入只需贡献标准记录、候选或指标，无需复制推荐和主动投递链路。

前端使用 Vite / React 构建，后端通过 FastAPI / Uvicorn 提供 API。

### 12. 工具系统

项目内置一批实用工具，覆盖 Agent 常见能力：

- Web 搜索
- 网页抓取
- 图片理解
- Shell 命令执行
- 后台 Shell 进程输出读取和停止（`process_output/process_stop`）
- 记忆召回
- 记忆遗忘
- 消息检索
- Skill 加载
- 工具搜索
- 统一任务创建与管理（`task_create/task_manage`）
- 个人上下文、即时推荐和周期报告（`personal_guidance`）
- 场景、专注、AI 主动关注和反馈（`personal_rhythm`）
- 任务内部可使用隔离的 Subagent 步骤执行器
- 定时任务管理

这些工具通过统一 Tool Registry 暴露给模型；MCP 工具连接后进入同一个实时能力目录。

## 运行结构

初始化后，运行时数据默认放在：

```text
~/.xiaoman/workspace/
```

常见文件包括：

```text
memory/
  HISTORY.md
  RECENT_CONTEXT.md
  SELF.md

proactive.db
personal.db
proactive_sources.json
proactive_quota.json
schedules.json
sessions.db
mcp_servers.json
skills/
drift/skills/
```

项目本体负责代码和默认能力，workspace 负责保存个人数据、记忆、任务、系统组件运行数据和会话状态。

## 快速启动

需要 Python 3.12。

当前本地已验证可使用 Conda 环境：

```powershell
conda activate Xiaoman
python main.py
```

也可以不激活环境，直接运行：

```powershell
E:\anaconda3\envs\Xiaoman\python.exe main.py
```

启动成功后会看到类似：

```text
IPC server listening on tcp://127.0.0.1:8765
Agent 已启动  |  CLI 连接地址: 127.0.0.1:8765
Uvicorn running on http://0.0.0.0:2236
```

Dashboard 地址：

```text
http://127.0.0.1:2236
```

## 配置说明

主配置文件为：

```text
config.toml
```

关键配置区域：

- `[llm]`：模型提供商
- `[llm.main]`：主模型
- `[llm.fast]`：轻量模型
- `[llm.vl]`：视觉模型
- `[agent]`：助手行为、最大 token、最大迭代次数
- `[channels.*]`：Telegram、QQ、CLI 等频道配置
- `[memory]`：长期记忆配置
- `[proactive]`：主动推送配置
- `[plugins.*]`：内部系统组件配置（兼容现有配置结构）
- `[integrations.*]`：外部集成配置

不要把真实 API key 提交到公开仓库。

## 适合改造成 Xiaoman 的方向

如果要把它改造成个人助手 Xiaoman，可以优先做这些事情：

1. 调整系统提示词，让助手具备稳定的人格、语气和边界。
2. 打开长期记忆，让它能记住你的偏好、项目、计划和上下文。
3. 配置 Telegram、QQ 或飞书中的一个作为主要入口。
4. 打开 Dashboard，作为本地管理后台。
5. 在“我的一天”建立个人资料，试运行晨间简报、晚间回顾和承诺捕获。
6. 逐步添加 Skill 和 MCP，例如日程、笔记、RSS、工作系统、网页监控。
7. 开启 proactive，让它能在重要事件发生时主动联系你。
8. 编写 Drift skills，让它在空闲时做整理、复盘和资料维护。

## 项目亮点总结

Xiaoman Agent 的优势不在于单次问答，而在于它已经具备个人助手所需的长期运行骨架：

- 能聊天
- 能记住事
- 能调用工具
- 能主动找你
- 能做后台任务
- 能接多个频道
- 能通过 Skill 和 MCP 持续扩展
- 能用 Dashboard 管理状态
- 能把个人数据保存在独立 workspace 中

这使它很适合作为 Xiaoman 个人助手的基础工程。
